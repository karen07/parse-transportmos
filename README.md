# Moscow Transport Reachability Map

A Python generator for an interactive Moscow public transport reachability map
based on OpenStreetMap. It combines transit routes with a pedestrian network
to explore possible journeys and estimated travel times.

Python-генератор интерактивной карты транспортной доступности Москвы по данным
OpenStreetMap. Объединяет маршруты общественного транспорта с пешеходной сетью
для поиска возможных поездок и оценки времени в пути.

## Описание

Проект позволяет выбрать начальную точку на карте и увидеть, какие остановки
и маршруты достижимы при заданных ограничениях. Для выбранного пункта
назначения можно построить варианты поездки с пешеходными участками и
пересадками. Основой служит топология OpenStreetMap, а не заранее составленный
список московских маршрутов.

Поддерживаются автобусы, трамваи, троллейбусы, метро, МЦК, МЦД и пригородные
поезда. Маршруты могут включать пешие переходы и до двух пересадок. Время
поездки рассчитывается приблизительно по модели движения, без расписаний,
пробок и данных о фактическом движении транспорта.

## Разработка и проверка изменений

**Опорные символы для изменения поведения:**

1. `build_transport_extract`, `build_transport_data` - подготовка данных из OSM и построение
   транспортной модели в `build-transport-map.py`.
1. `pack_html_payload`, `build_html` - упаковка данных, создание конфига и публикация сайта;
   при изменении формата сверяйте декодер в `web/routes-data-worker.js`.

**Основные точки изменения:**

- `build-transport-map.py` - загрузка OSM, построение графов, упаковка данных,
  конфигурация сборки и копирование веб-ресурсов.
- `web/page.html`, `web/routes.js`, `web/routes.css`, `web/routes-data-worker.js` -
  исходники страницы, маршрутизации, стилей и воркера данных.
- `web/boot-loader.js`, `web/boot-loader.css` - заставка с настоящими магистралями.
- `major_roads.py` - извлечение основных магистралей из локального OSM PBF,
  соединение общих узлов и экспорт упрощенных линий для заставки.
- `assets/` - исходные favicon и иконка для домашнего экрана.
- `tests/` - самостоятельные регрессионные тесты JavaScript.

**Что генерируется и служит для проверки результата:**

- `site-osmlab/routes.html`, `routes.js`, `routes.css`, `boot-loader.js`,
  `boot-loader.css` и `routes-data-worker.js` - копии или результат сборки;
- `site-osmlab/routes-config.json` - параметры конкретной сборки;
- `site-osmlab/routes-maplibre-worker.js` - внешний воркер MapLibre;
- `site-osmlab/routes.json.gz` - сжатые данные для браузера.
- `site-osmlab/moscow-major-roads.json` - автоматически созданная геометрия
  МКАД, транспортных колец и крупных магистралей для заставки.

Не редактируйте сгенерированные файлы в `site-osmlab/`: следующая сборка
перезапишет их. Каталог `cache/` также создаётся генератором.

**Проверка изменений:** Изменение формата данных требует согласовать
`build-transport-map.py` с `web/routes-data-worker.js` и `web/routes.js`.
После правок проверьте `python3 build-transport-map.py --help`, тесты,
генерацию и работу карты в браузере. Кеш не является источником логики.

**Типовые изменения:**

- Интерфейс, заставка и стили: меняйте файлы `web/`, затем запускайте
  `--refresh-web-assets` без повторной обработки OSM. Геометрия заставки
  создается из PBF при полной сборке, а не при обновлении веб-файлов.
- Схема данных: согласуйте `pack_html_payload`, упаковщики и JS-декодер;
  изменение только формата записи нарушит чтение.

### Источник веб-кода и поток данных

- Источник HTML, CSS и JavaScript - обычные файлы `web/`. Python не
  хранит их текст внутри строковых констант. `web/page.html` содержит
  только небольшие плейсхолдеры для имён ресурсов и параметров сборки.
- `pack_html_payload` упаковывает геометрию маршрутов, пешеходный граф
  и пересадки. `build_html` записывает сжатый `.json.gz`, отдельный
  `routes-config.json` и публикует файлы из `web/` и `assets/`.
- Браузер читает конфиг и загружает `routes.json.gz` через worker из
  `web/routes-data-worker.js`. Worker распаковывает gzip, восстанавливает
  структуры данных и передаёт буферы графа основному потоку.
  При изменении payload одновременно меняйте упаковку и декодер.

### Инварианты для правок

- Форматы `delta-varint-dm-v1` (пешеходный граф), `csr-delta-varint-cm-v1`
  (пересадки) и `route-delta-varint-e7-v1` (геометрия) имеют собственные
  соглашения о единицах, смещениях и порядке полей. Менять кодирование
  только на стороне Python или только на стороне JavaScript нельзя.
- Суффикс `-v1` в именах файлов кеша не равен внутренним версиям
  пешеходного кеша и кеша пересадок (`WALK_CACHE_VERSION` и
  `WALK_TRANSFER_CACHE_VERSION`). При изменении схемы сверяйте обе проверки.
- `--refresh-web-assets` копирует фронтенд и обновляет HTML/конфиг без
  повторной обработки OSM и без изменения `routes.json.gz`. Нужен готовый
  файл данных рядом с указанным `--output`. Если уже существует
  `routes-config.json`, gzip даже не читается; параметры берутся из
  имеющегося конфига, а не из новых CLI-флагов. Для изменения `grid_size`,
  скорости и лимита ходьбы или непрозрачности нужна обычная сборка.
  Старые сборки без конфига обновляются через совместимый legacy-путь.
- Python-регрессии находятся в `run_self_tests`; проверки JavaScript -
  в `tests/map-ready.test.cjs`, `tests/yield.test.cjs` и
  `tests/web-assets.test.cjs`.

## Требования

- Python 3.
- [`osmium`](https://pypi.org/project/osmium/) (pyosmium 4.x) для чтения
  и объединения файлов OSM PBF.
- Доступ к сети при первой загрузке данных OSM и геометрии МКАД.
- Современный браузер с поддержкой `DecompressionStream('gzip')`.

Установка Python-зависимости:

```bash
python3 -m pip install -U osmium
```

Скрипт не требует отдельного backend-сервера для вычисления маршрутов:
после генерации расчёты выполняются в браузере. Однако при открытии карты
нужна загрузка Leaflet, MapLibre GL, интеграционного адаптера и картографической
подложки из внешних источников.

## Быстрый старт

Запустите генератор `build-transport-map.py` из каталога проекта:

```bash
python3 build-transport-map.py --cache-dir cache -o site-osmlab/routes.html
```

При первом запуске генератор загрузит региональные PBF, выделит крупные
автомагистрали для заставки, подготовит транспортные
и пешеходные данные и сформирует HTML. Повторные сборки могут использовать кеш.
Большие входные PBF и построение графов требуют времени и свободного места.

Для локального просмотра раздайте сгенерированный каталог через HTTP-сервер:

```bash
cd site-osmlab
python3 -m http.server 8000
```

После запуска откройте `http://localhost:8000/routes.html`.
Открывать HTML напрямую через `file://` нельзя: сайт получает
`routes-config.json` и `routes.json.gz` по `fetch()`.

Если транспортный кеш уже создан, геометрию заставки можно обновить
самостоятельно, не перестраивая транспортный и пешеходный графы:

```bash
python3 major_roads.py \
    --input cache/moscow-regions-osmlab.osm.pbf \
    --output site-osmlab/moscow-major-roads.json
```

Файл `moscow-major-roads.json` генерируется, его не нужно редактировать или
хранить в Git. Источник геометрии - OpenStreetMap; атрибуция видна на заставке.

При сборке рядом с `routes.html` автоматически копируются `favicon.svg`,
`favicon.ico`, `favicon-32.png` и `apple-touch-icon.png` из каталога
`assets/`, в том числе при запуске с `--refresh-web-assets`. При публикации
сайта эти иконки нужно загружать вместе с остальными файлами.

## Использование

1. Щёлкните по карте, чтобы выбрать точку отправления.
1. Настройте виды транспорта. По умолчанию включён наземный транспорт;
   метро, МЦК и МЦД с пригородными поездами выключены.
1. Выберите допустимое время пешего хода (1-15 минут), количество пересадок
   (0-2) и максимальное время поездки (по умолчанию 60 минут).
1. Исследуйте достижимые остановки, маршруты и пешеходные пути.
1. Дважды щёлкните по точке назначения, чтобы увидеть варианты поездки;
   кнопка `Reset` сбрасывает начальную точку и маршрут.

Значение по умолчанию для пешего хода - 5 минут при модельной скорости
80 м/мин. Доступность и время рассчитываются на основе OSM и оценочных
скоростей движения, а не расписаний, пробок или текущего движения транспорта.

### Основные параметры

| Параметр | Назначение |
| --- | --- |
| `-o`, `--output` | Путь к HTML (`routes.html` по умолчанию). |
| `--cache-dir` | Каталог кеша (`cache`). |
| `--update` | Заново скачать региональные исходники и обновить зависимые данные. |
| `--rebuild` | Пересобрать транспортный extract без принудительной загрузки PBF. |
| `--rebuild-walking` | Пересобрать пешеходный граф. |
| `--rebuild-transfers` | Пересчитать пешие пересадки между остановками. |
| `--refresh-web-assets` | Обновить только веб-файлы, сохранив транспортные данные. |
| `--walk-minutes` | Начальное ограничение пешего хода, в минутах (`5`). |
| `--walk-speed` | Модельная скорость ходьбы, м/мин (`80`). |
| `--circle-opacity` | Непрозрачность слоя покрытия: `0` - невидим, `100` - полностью непрозрачен (`50` по умолчанию). |
| `--mkad-buffer-km` | Буфер от МКАД, 0-50 км (`10`). |
| `--through-service-policy` | Оценочное продолжение рейса на конечной (`estimated`) или строгий режим (`strict`). |
| `--report-json` | JSON-отчёт об извлечении и качестве данных. |
| `--dump-geojson` | Выгрузка нормализованных маршрутов и остановок. |
| `--self-test` | Встроенные регрессионные тесты. |

Кеш транспортного экстракта создаётся под именем
`cache/moscow-transport-osmlab-v1.osm.pbf`. Пешеходный граф и пешие
пересадки также используют суффикс `-v1`. Для полной пересборки можно
удалить каталог `cache/` и повторно запустить генератор.

**Тестовые GeoJSON-фикстуры:** `--input-geojson` читает нормализованные
маршруты и остановки вместо OSM PBF. Для построения пешеходных маршрутов
в этом режиме требуется `--walking-json` с подготовленным пешеходным графом.
Исключение - диагностический режим `--inspect-route-ref`, в котором это
требование не применяется. `--input-geojson` нельзя совмещать с `--update`
и `--rebuild`; с `--diagnose-station` он также несовместим, поскольку для
диагностики станции требуются исходные OSM-данные. Эти ограничения
проверяются в `parse_args` до начала обработки данных. Также `--update`
и `--rebuild` взаимоисключающие, а `--diagnose-only` допустим только
вместе с `--diagnose-station`. Для `--walk-minutes`, `--walk-speed` и
`--grid-size` требуются положительные значения; для `--circle-opacity`
допустим диапазон 0-100. Диапазоны `--diagnose-radius` и
`--audit-rail-radius` равны 100-2500 метров. При изменении аргументов
сверяйте не только `add_argument`, но и проверки после `parse_args`.

Полный список флагов, включая диагностику станций и тестовые фикстуры:

```bash
python3 build-transport-map.py --help
```

Чтобы обновить только интерфейс после изменения файлов `web/` или `assets/`,
используйте из корня проекта:

```bash
python3 build-transport-map.py --refresh-web-assets -o site-osmlab/routes.html
```

Для этого предварительно должна существовать полная генерация сайта.
Код из `web/` и исходные иконки из `assets/` копируются в `site-osmlab/`,
а `routes.json.gz` остаётся без изменений.

## Возможности

- **Разные виды транспорта:** автобус, трамвай, троллейбус, метро, МЦК,
  МЦД и пригородные поезда. МЦД и другие пригородные поезда объединены в один
  переключатель интерфейса, но остаются разными типами в модели данных.
- **Транспортная доступность:** маршруты без пересадок, с одной или двумя
  пересадками; ограничение общего расчётного времени поездки.
- **Пешеходная доступность:** перемещения по графу пешеходных путей OSM,
  с учётом разрешённого направления и ограничений доступа. Покрытие строится
  вдоль доступных путей, а не в виде кругов вокруг остановок.
- **Маршруты до точки:** выбор начальной точки одиночным щелчком и пункта
  назначения двойным щелчком; отображение альтернатив поездки.
- **Настройка модели:** выбор видов транспорта, максимального времени пешего
  хода, числа пересадок, лимита времени поездки и непрозрачности покрытия.
- **Диагностика исходных данных:** отчёты по остановкам, геометрии,
  несвязным участкам пешеходной сети и доступу к железнодорожным станциям.
- **Кеширование:** повторное использование скачанных PBF, извлечённых
  маршрутов, пешеходного графа и заранее вычисленных пересадок.
- **Статический результат:** генератор сохраняет отдельные HTML, CSS,
  JavaScript, worker и файл данных `.json.gz`. Для подложки и библиотек
  используются внешние ресурсы, поэтому это не полностью автономное
  офлайн-приложение.

## Загрузка карты и диагностика

Заставка закрывается после появления видимых объектов векторной карты,
не требуя обязательного события MapLibre `idle`. Это отдельно от загрузки
и распаковки транспортного графа. Если тайлы или WebGL недоступны более
30 секунд, показываются ошибка и кнопка повторной загрузки.

Анимация в `web/boot-loader.js` рисует настоящую дорожную геометрию OSM:
все магистрали и кольца имеют одинаковую толщину и цвет. Соседние
проезжие части сводятся в общую маску отрисовки, чтобы наложение линий
не делало участки светлее. Подсветка распространяется радиальной волной
из центра Москвы, затухает и повторяется; вся карта не заполняется.
Это декоративная анимация, а не рассчитанная изохрона или процент загрузки.

Полоса имеет точный процент **только во время скачивания**, когда сервер
возвращает размер файла. Для распаковки, инициализации и отрисовки она
анимируется без выдуманных процентов.

Для расчётов в Safari используется `MessageChannel` вместо многократного
`setTimeout(0)`, который может давать задержку около 4 мс на каждом yield;
Chrome продолжает использовать `scheduler.yield()`. Переход к таймеру
сохранён как последний fallback.

Логика ожидания отрисовки и заставки находится в `web/boot-loader.js`,
а поиск маршрутов и уступки управления - в `web/routes.js`.
Для них есть отдельные Node.js-тесты; дополнительно нужна проверка
сгенерированной страницы в целевых браузерах, включая Safari.

## Архитектура и реализация

### Источники данных и область покрытия

Транспортные данные загружаются из региональных выгрузок OSMlab:

- [`RU-MOW`](https://www.osmlab.ru/regions/RU-MOW.pbf) - Москва.
- [`RU-MOS`](https://www.osmlab.ru/regions/RU-MOS.pbf) - Московская область.

Генератор объединяет PBF по идентификаторам OSM-объектов и удаляет дубликаты.
По умолчанию транспортная сеть ограничивается реальным полигоном МКАД и
буфером **10 км**, а не окружностью вокруг центра города. Граница берётся из
[`moscow-geo`](https://github.com/karen07/moscow-geo).

Размер буфера можно изменить:

```bash
python3 build-transport-map.py --mkad-buffer-km 20 -o site-osmlab/routes.html
```

Также доступны `--mkad-geojson` для локального GeoJSON и `--no-mkad-clip`
для отключения ограничения. Важно: исходные региональные выгрузки и конечная
область покрытия - разные вещи.

### Как устроена обработка

1. **Загрузка и объединение OSM.** Скачивание с повторными попытками и
   возобновлением HTTP Range, объединение регионов и построение кеша.
1. **Извлечение маршрутов.** Разбор OSM `route` и `route_master`, остановок,
   платформ и последовательностей геометрии. Отдельно учитываются направления
   маршрутов и признаки МЦК/МЦД.
1. **Пространственная фильтрация.** Обрезка геометрии по области МКАД с
   буфером. Если маршрут выходит за границу, его участки не соединяются
   искусственным переходом через исключённую территорию.
1. **Пешеходный граф.** Построение сети по доступным OSM-путям, обработка
   платформ, входов и `stop_area`, поиск связей между остановками.
1. **Транспортный индекс.** Подготовка остановок, направлений и переходов
   для поиска достижимости в браузере (алгоритм в стиле RAPTOR).
1. **Генерация веб-ресурсов.** Компактная упаковка геометрии и графов,
   JSON-сериализация, gzip-сжатие и запись данных в отдельный `.json.gz`.
   `build_html` копирует HTML/CSS/JS из `web/`, иконки из `assets/`
   и создаёт `routes-config.json`. Браузер читает данные через worker.
   В сжатом JSON бинарные поля представлены в Base64, но содержимое
   не встраивается в HTML.

Система старается не создавать несуществующие пешеходные или транспортные
соединения из-за близости объектов на карте. Некоторые пересадки могут быть
оценочными, например на основании `stop_area_group`; это не подтверждение
физически доступного перехода.

## Тестирование

Запуск встроенных тестов:

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 build-transport-map.py --self-test
```

Проверки загрузки карты, уступки управления браузеру и веб-ресурсов:

```bash
node tests/map-ready.test.cjs
node tests/yield.test.cjs
node tests/web-assets.test.cjs
```

Тест `web-assets.test.cjs` требует предварительно созданного `site-osmlab/`.

Сохранение отчёта вместе с генерацией HTML:

```bash
python3 build-transport-map.py \
  --cache-dir cache \
  --report-json report.json \
  -o site-osmlab/routes.html
```

Исследование конкретной железнодорожной станции:

```bash
python3 build-transport-map.py \
  --cache-dir cache \
  --diagnose-station 'Москворечье' \
  --diagnose-only
```

Диагностика формирует JSON и GeoJSON с подробностями привязки станций к
пешеходной сети; доступны флаги `--diagnose-output`, `--diagnose-geojson` и
`--diagnose-radius`. Для проверки всех железнодорожных остановок предусмотрен
`--audit-rail-access report.json`.

Отладочный `--allow-moskvorechye-private` разрешает несколько явно указанных
`access=private` путей **только для эксперимента**. Он не доказывает, что
по ним можно ходить в действительности, и не предназначен для обычной сборки.

## Ограничения

- Маршруты, геометрия, пешеходные соединения и качество результата зависят от
  полноты и актуальности OpenStreetMap.
- В модели используются оценочные скорости, фиксированные ожидания транспорта
  и задержки на остановках. Она не учитывает реальные расписания, интервалы,
  пробки, задержки и закрытия.
- Неполные OSM-отношения и недостающие пути могут приводить к пропущенным
  остановкам, разрывам маршрутов или недоступным пересадкам.
- Режим `estimated` допускает оценочное продолжение на конечных; для более
  консервативной модели используйте `--through-service-policy strict`.
- Создаётся статический снимок данных на момент сборки, а не сервис
  мониторинга общественного транспорта в реальном времени.
